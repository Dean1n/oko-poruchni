# Исправления OKO_PORUCHNI от 20.09.2026

Сохранена исходная схема: детектор движения → YOLO Pose и ByteTrack → центр рамки человека в зоне лестницы → запястья в зоне поручня → таймер нарушения → видеофрагмент. Файл модели, координаты зон и пороги камер не менялись. Нейросеть не переобучалась.

## Что исправлено

- Таймер использует время кадра `frame_index / FPS`, а не скорость работы компьютера. Расчёт предполагает постоянную частоту кадров записи.
- Поручни проверяются только у лестницы, в которой находится человек.
- Если видимости запястий недостаточно, состояние — `unknown` (оранжевая рамка), таймер сбрасывается. Если хотя бы одна уверенно найденная рука находится в зоне своего поручня — `holding`. Если обе уверенно видны вне поручня — `not_holding`. Порог уверенности 0.5 и минимум три последовательных наблюдения сохранены.
- Потеря человека и смена лестницы прерывают таймер. Старые треки не считаются видимыми. Состояние очищается между видео.
- Интерфейс ожидает фактическое завершение обработки. Отмена и ошибка не выдаются за успех. Остановка не освобождает ресурсы работающего потока; окно закрывается после его завершения.
- Устранено повторное захватывание обычной блокировки при закрытии видеозаписей.
- Убрано накопление ненужных копий кадров для каждого человека и удвоение первого кадра. Короткие пропуски детекции не ускоряют сохранённый ролик. Для новых обработок создаются уникальные имена записей.
- Ошибки нейросети и создания видеофайлов явно завершают обработку с ошибкой.
- Старая база обновляется автоматически, перед обновлением создаётся `data/analytics.db.before_schema_v2.bak`. История сохраняется.
- Результаты завершённого анализа записываются в одной транзакции: видео, люди, эпизоды нарушений, пути к фрагментам и суточная статистика. Один непрерывный эпизод — одна запись. Повторная обработка заменяет результаты без удвоения итогов.
- При отмене неполный анализ не заменяет прежние результаты в базе. Уже записанные фрагменты могут остаться в папке нарушений.
- Камеры из `config/cameras.json` синхронизируются с базой при запуске.
- Пути стандартного комплекта разрешаются относительно папки программы. Исправлены расхождения `BK`/`ВК` в названиях двух существующих папок видео; идентификаторы камер сохранены. Внешние пользовательские пути сохраняются.
- Используется комплектный `models/model.pt` и явный путь к настройкам ByteTrack. Значения порогов ByteTrack сохранены; удалён повтор параметра `track_buffer`, добавлен необходимый `fuse_score`.

## Запуск

На рабочем компьютере Windows запустить `Запуск.bat` в папке программы. Он сначала переходит в свою папку; при ошибке окно остаётся открытым. Существующее рабочее окружение Python/CUDA не заменялось.

Для нового отдельного окружения использованы Python 3.12 и версии из `requirements.txt`. Эти версии проверены на macOS с CPU; запуск на Windows и конкретной видеокарте отдельно не проверялся. Если текущее окружение уже работает, переустановка зависимостей не обязательна. Не заменять рабочую сборку PyTorch/CUDA без необходимости.

## Проверки

Выполнены 32 автоматические проверки: таймер при разной скорости вычислений, левая/правая/скрытая рука, чужая лестница, потеря трека, два человека, миграция старой базы с резервной копией, откат при ошибке записи, повторная обработка, создание читаемого видео, отмена, состояния интерфейса и закрытие окна.

Дополнительно исходная модель `model.pt` обработала 50 кадров ролика, составленного из стандартного изображения `bus.jpg`, поставляемого с Ultralytics. В этой проверке движение подано принудительно, а нейросеть, трекер, проверка зон, запись видео и база работали реально. Обнаружены 4 человека и 2 эпизода, видеофрагменты открываются. Это проверка технической работоспособности, а не оценка точности на ваших лестницах.

В переданном комплекте нет исходных записей с камер. Для проверки качества нужны реальные проходы: с удержанием каждой рукой, без удержания, со скрытой рукой и несколькими людьми. Запястье в зоне поручня остаётся косвенным признаком удержания; пальцы и физический захват программа не распознаёт.

Для запуска тестов в отдельном окружении: `python -m pip install -r requirements-test.txt`, затем `python -m pytest -q tests`.

## Резервные копии

Перед обновлением рабочего развёртывания следует сохранить отдельную копию всей
папки приложения. База дополнительно создаёт резервную копию перед миграцией
схемы. Эти архивы относятся к развёртыванию и не должны попадать в Git.

Для возврата к старой версии сначала закрыть программу, затем восстановить код,
конфигурацию и базу из одной согласованной резервной копии.
